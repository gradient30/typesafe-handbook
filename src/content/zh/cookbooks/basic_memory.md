# 简单记忆系统

> 让 Jev 决定哪些请求和答案值得记住，然后用一个小函数包装 Jev 调用，将记忆添加到后续调用中。

每个 Jev 请求只看到你发送给它的 state。客户上个月告诉你的应用的内容（例如他们的版本或计划）不会出现在下一个请求中，除非你的代码将其放入其中。这里的记忆系统通过每个调用额外的一个 Jev 请求和一个 Python 字典来实现这一点。

我们的示例路由支持工单。在八月，客户说他们在 Windows Server 上自托管。在九月他们写“仪表板从今天早上开始真的很慢”。没有记忆时，Jev 将该工单发送给云团队而不是自托管团队。在下面的示例中，添加记忆将所有六个后续工单发送到预期的团队。单独路由每个工单只得到六个中的两个正确。

简单记忆系统有两个部分：

* 每次调用后，Jev 一起看到原始请求及其答案。一个 `Noul` 问题（我们称之为门）询问请求是否陈述了关于客户的重要事实，应该被记住。如果 P(yes) 至少为 0.5，工单和 Jev 的答案被保存为该客户的记忆。
* 一个包装函数 `ask_with_memory()` 接受与 `ask()` 相同的 `state` 和 `questions` 参数（`ask()` 是 TypeSafe Python SDK 的 `client.system_one` 方法，模型固定且调用被缓存），并返回 Jev 响应。在每次调用前，它将该客户保存的工单和 Jev 对它们的答案添加到 state 中。

该包装是一个基本的代理 harness。harness 是围绕模型的代码，为它提供额外能力，如工具调用和循环运行。这个基本的玩具版本只在普通 Python 字典中给它记忆，每个客户 ID 一个列表。

包装进行两个连续的 Jev 请求：路由请求，然后是门，门与 Jev 的答案一起判断工单。包装返回路由响应，无论是否保存了任何内容。

因为 `ask_with_memory()` 接受与 `ask()` 相同的参数并返回相同的响应，你可以在不更改任何其他代码的情况下将一个替换为另一个。包装找到客户的记忆，将它们添加到 state 中，并自行保存新的记忆。

示例通过包装发送两个客户的五个早期工单，然后从每个客户路由三个后续消息两次：一次带有它保存的记忆，一次没有。一张表将所有六个的两个答案并排放置。

## 架构

- **门控**：额外 Noul 判断工单是否包含值得记住的客户事实（版本、计划、合同等），阈值 0.5。
- **包装**：`ask_with_memory` 在调用前注入记忆到 state，调用后根据门控结果保存。
- **存储**：每个客户 ID 一个列表的 Python dict。

## 结论

添加简单记忆显著提高了路由准确率（从 2/6 到 6/6），因为后续工单可以利用之前陈述的持久客户事实。包装可无缝替换原始 `ask`，适合作为基本代理 harness 的起点。
